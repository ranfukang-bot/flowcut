# 代码块分条、变体两轮与本机拼接

适用于 1.4.41 起的商品任务（Gemini 网页模式，单条时长）。双段 30 秒、爆款复刻和剧本流水线不走这里的逻辑。

## 一个代码块一条视频

- 桌面端在 Gemini 回复完成后读取最后一条回复中的代码框（`pre` 里的 `code` 文本），不读取 “Plaintext” 标签、复制按钮、正文和表格；同时把整段回复作为原始回复写回。
- 判定规则在 `lib/prompt-blocks.ts`，桌面端写回前和本机服务收到结果时各检查一次：
  - 0 个代码块且回复里看不到代码框：整段回复作为 1 条提示词，并提示“未识别到代码块，按整段回复处理”。
  - 看得到代码框（含 ``` 或 Plaintext/复制代码 等标签行）但没读到内容：停止，不提交。
  - 每个代码块至少 300 字，最多 10 个，内容不能重复；任一不满足则整轮不拆分、不提交，错误和原始回复保存在任务上，按原有 30 秒 / 1 分钟 / 2 分钟延后重试。
- 1 个代码块：仍是普通任务。2 个及以上：原任务变成“任务组”（`task_role='group'`，状态 `split_done`），每个代码块插入一条子任务（`task_role='clip'`，ID 为 `组ID-r轮次-序号`）。插入和组状态更新在同一个 D1 批次内，并要求该组仍由同一执行器领取，所以重复写回不会多建视频。
- 子任务和普通任务一样进入 Seedance、下载、审核和放行；成片仍按商品 ID 命名。任务组只是容器，不计入任务数；组内视频全部删除后组自动删除。

## 变体两轮

- 创作中心勾选“变体两轮”并选择变体 Gem。创建任务时保存变体 Gem 内容快照和第二轮文字（`{时长}{地区}{拍摄风格}` 在创建时代入，`{母版提示词}` 在第二轮代入）。
- 第一轮：所选 Gem 只能输出 1 个代码块（或无代码块的整段），结果保存为组的母版提示词，状态进入 `variant_queued`。
- 第二轮：任务以 `variant` 类型再次领取，发送第二轮文字和同样的商品图片给变体 Gem；回复按上面的规则拆成本轮的视频。
- “用同一份母版重新分裂”重新排队第二轮，新视频编号为下一轮，已有视频保留。

## 本机拼接

- 在任务组详情里勾选 2–10 条待检查视频，点击“拼接所选”。顺序按批次和序号，不按勾选顺序。
- 流程：服务端预留（新建 `concat_running` 的拼接任务，所选视频标记为 `merging`）→ 本机 FFmpeg 合成到该拼接任务的待检查目录 → 校验总时长 → 标记完成（原视频变为 `merged`）。合成失败会取消预留，原视频保持待检查。
- 拼接成片和其他成片一样审核；通过后删除参与拼接的原视频文件和记录。删除拼接成片则原视频回到待检查。
- 启动时自动处理中断的拼接：成片文件已写好则完成，否则取消；已通过但未清理的原视频继续清理。
