# 多品裂变

从 1.4.46 起，左侧“爆款复刻”下方的“多品裂变”是独立入口。它把一份母版应用到 2–10 个不同商品，每个商品各产一条视频，与创作中心的变体两轮和代码块分条分别使用。

## 创建（1.4.47 起）

1. 放入商品：把图片或文件夹拖进大框，或点击选择。按文件名里的商品 ID 分组（`ID.png`、`ID (2).png`、`ID-2.jpg`、`ID_2.webp`，至少 8 位数字）；文件名没有 ID 时用文件夹名；都没有时这一批图片单独成一张卡，需要补填 ID。拖到某张卡片上的图片只加到这张卡。每张卡最多 12 张图，一批 2–10 个商品，ID 不得重复；商品库已有的 ID 显示商品名，上传仍复用商品保存和去重接口。也可以「从商品库添加」，使用商品库已保存的图片。
2. 选择母版 Gem、变体 Gem 和 TK 账号。默认用 ★ 卡片（初始为第一张）生成母版，可在卡片上「设为母版」切换。
3. 「更多设置」里有时长、地区、拍摄风格、生成方式、母版来源（可粘贴至少 300 字的现成母版，跳过生成母版这一轮）和第二轮文字。第二轮文字必须包含 `{母版提示词}`，支持 `{时长}`、`{地区}`、`{拍摄风格}`。只支持单条时长，不支持双段 30 秒。
4. 这些设置保存在本机浏览器存储中，下次自动带出；已删除的 Gem 或账号不会被带出。缺少的项目显示在「生成 N 条视频」按钮旁，问题卡片标红。提交前确认商品数量、母版来源和视频额度。

## 数据与阶段

从 1.4.51 起，第一轮发送文字默认与创作中心的「发送给 Gem 的文字」共用。更多设置可填写仅用于多品裂变的版本，或点「沿用创作中心」恢复共用；时长、地区和拍摄风格在创建任务时展开并保存，不会改动已存在的失败任务快照。选中同一个母版与变体 Gem 时会提示检查，但允许有意复用。

口播语言默认自动：菲律宾 Taglish、印尼 印尼语、马来西亚 马来语、泰国 泰语、越南 越南语、新加坡 英语、墨西哥 西班牙语（墨西哥）、巴西 葡萄牙语（巴西）、美国 英语。可在下拉框改选表内语言或中文。修改 `lib/spoken-language.ts` 的 `REGION_SPOKEN_LANGUAGES` 即可添加市场，地区与语言菜单同步扩展。未知地区使用「该地区最常用的本地日常口语」并提示补表。

发给商品 Gem 的消息总会补齐语言和「不要提问，直接按以上信息输出提示词，每条提示词放在单独的代码块里」。历史任务领取时同样补齐，原有 Gem、图片及提示词快照不重写。没有代码块时先保留原回复，在同一对话补充一次默认语言和代码块要求；第二次仍无代码块则失败，错误为「Gem 没有输出提示词（回复里没有代码块）」，保留两轮原文。此类失败不再自动新建对话；有代码块但内容过短等校验仍然阻止视频提交。旧整段回复的服务端兼容逻辑仍只用于历史结果，新网页执行器必须先获得代码块。

Gemini 结束生成后回复不足要求时，错误会显示字数和短回复全文，并把原文保存在 `gemini_raw_reply`。可在任务中查看；程序仍延后重试，不会把反问或其他短回复放行给 Seedance。升级前已丢失的原文无法从任务记录还原，须查看原 Gemini 对话。

沿用 `tasks` 表及现有快照列，不建立新表。

| 行 | 状态与用途 |
| --- | --- |
| `fission` 组 | `prompt_queued → prompt_generating → fission_ready`；粘贴母版直接 `fission_ready`。`prompt` 保存共用母版，图片快照只含所选母版商品。 |
| `fission_child` 商品 | `fission_wait` 等待母版；母版就绪后 `variant_queued → variant_generating → prompt_ready`，自动模式再进入原 Seedance 队列、下载和审核。 |

父行和全部子行在同一个 D1 batch 创建。生成母版后，在同一个 batch 保存母版并释放仍为 `fission_wait` 的子行，且要求母版仍在生成阶段、由本次执行器领取。重复回报和旧执行器的 release/defer/retrying/error 不会重新打开已经完成的父子任务。

每条子行保存自己的 `product_id`、`product_external_id_snapshot`、`image_keys_snapshot`，以及创建时的变体 Gem 内容和第二轮文字。领取时 JOIN 父行读母版，图片仅取本子行快照；后来修改商品图、商品 ID 或 Gem 不会串入已创建批次。

母版与子提示词均使用 `blockMode='single'`：只能收到一个至少 300 字的代码块。从 1.4.52 起，发送文字明确要求一整条视频（含全部镜头与口播）放在唯一代码块中；若 Gem 仍把预设、场景、时间轴拆成多个块，在原对话要求合并一次。补充后仍有多个块就停止失败，保留两轮原文，不自动新开对话；没有代码块沿用上面的一次语言纠正。最多补充一次，不叠加两种纠正。代码块仍须通过原长度与完整性校验；程序不会自行拼凑章节。子提示词直接写入自己的行，不创建 clip。

## 查看、重做与恢复

- 批次在本模块和任务队列中显示为一组，每个商品显示自己的名称、商品 ID 和状态。组容器不计入任务数，任一子任务符合筛选条件时，其组也会显示。
- 商品互不阻塞。母版失败时，子任务继续等待；恢复母版后再放出子任务。子提示词失败可单独恢复；已提交的视频继续走原 Task ID 的 Seedance 恢复流程。
- 视频就绪后，“重新生成该任务”使用同一份提示词创建一个新视频任务，不运行 Gemini。“用母版重新写这条提示词”会确认额外额度，再创建一个新子任务运行变体 Gem；两者均沿用原图片和商品 ID，同组同位置，旧成片按原重做规则清理。
- 每条视频独立审核、删除。整组删除连带删除其中的记录；最后一个子任务删除后移除空组。放行使用原审核模块，按该子任务的商品 ID 命名并放入所选 TK 账号的目录。裂变组不允许拼接。
- 母版商品仍关联裂变批次时，商品库会阻止删除并提示先处理批次，防止其他商品任务失去父行。删除非母版商品只清理该商品自己的子任务，其他商品照常保留。
- 恢复备份时，`fission_wait`、`fission_ready` 和其他未完成阶段均标记失败，禁止自动重发。有完整母版时，人工恢复组会保留它；子任务仍需按状态人工恢复。

## 验证

`gemini-web-workbench/tests/fission-api.test.js` 用真实 API 路由、`lib/storage.ts` 建表的内存 SQLite、临时文件及 `VideoReview` 验证四商品独立快照、母版屏障、单条回复、失败恢复、幂等与过期回报、分组计数、删除、重做和审核命名。页面交互测试也仅使用隔离数据。

真实账号测试只在用户明确授权后进行；开发测试不读真实资料目录，不登录、删除或重建平台账号，也不改变现有模型或 Gem 内容。
