# 爆款复刻分段（1.4.61）

上传一条不超过 60 秒、100MB 的参考视频和 1–12 张商品图，选择地区、口播语言、Gemini 账号和 TK 归档账号。商品名称和 ID 可不填；商品图始终按现有商品库保存逻辑入库，相同 ID 复用商品，任务保留本次图片快照。只有地区可以保存为本模块默认值。

页面按视频元数据计算分段。例如 24 秒生成 15+9 秒两段，16 秒生成 8+8 秒，33 秒生成 15+9+9 秒。时长四舍五入，低于 4 秒按 4 秒；尾段不足 4 秒时将最后两段均分。读取不到元数据时不猜总时长，第一轮按实际视频拆解。

## 网页 Gem 和两轮对话

内置 ID 为 `builtin-reference-remix`，名称为「爆款视频复刻智能体」。`lib/remix-gem.ts` 直接读取 `lib/reference-remix-segments-gem.txt` 全文，接口和界面都禁止编辑或删除。模板中心的「网页 Gem」可以查看每个账号的绑定和手动找回链接。首次使用仍由 `SavedGems.ensure` 自动创建，保存结果待核对时仍遵守版本 hold，不重复创建。

新桥接类型 `remix-segments`、`remix-rewrite` 和普通模板任务一样进入真正的已保存 Gem，检查现有模型设置后才上传。模型、思考等级和 Gem 指令不做任何修改。

第一轮仅上传参考视频，发送总时长、分段计划和「不要提问，直接输出。」；时长未知则只发最后一句。每段必须有一个独立代码块，第一行形如：

```text
第1段｜原视频 0-15 秒｜本段时长 15 秒
```

主进程通过 `gemini:validate-remix` IPC 以当前 pending job 的内容校验，禁止页面自行指定预期区间。它等待服务端再次校验并持久保存原脚本后才确认成功。第一轮没有保存成功，页面不会进入第二轮。

第二轮保持同一对话，仅上传商品图。文字为「请1：1复刻该视频 包括运镜、动作细节、音效等：」、全部原脚本代码块、选填的商品名称、口播语言和「不要提问，直接输出。」。口播语言用 `lib/spoken-language.ts` 解析；选择「跟随原视频」时不加语言行。前后核对对话地址和回复历史；只做第二轮的全新 Gem 对话允许首次发送产生新的对话地址，后续纠正仍须留在该对话。

两轮共用 `lib/remix-segments.ts`。每块至少 300 字，最多 10 块；序号连续、整数时长 4–15 秒、首尾衔接且覆盖视频。已知元数据时比对计划（分段点允许 2 秒，总长允许 1 秒）；第二轮必须严格保留第一轮的全部区间。失败在原对话纠正一次，列出预期首行，要求完整重输（单段重写的纠正只要求输出这一段的一个代码块）；仍失败保留原回复并按现有 Gemini 延后重试。不得退回正文、截取部分块或补造时长。第一轮时长未知且没有可用首行时，纠正只能给固定首行格式和连续覆盖要求，不能凭空列出未知区间。

页面沿用原复刻第一轮 60、第二轮 150 的回复读取档位（现有参数实际为最短字数），每轮总等待上限沿用 8 分钟；每增加两段相应放宽总等待。普通任务的超时和代码块规则保持原样。

## 任务、版本和恢复

不新增表。`tasks.task_role='remix'` 是容器，`clip` 是每段视频，`concat` 是拼接视频。父组保存商品、Gem、图片、地区、账号、归档目录、自动排队设置的快照。首次自动领取固定 Gemini 账号，后续优先用它，不可用则在未被 hold 的空闲账号中选择；临时借用别的账号不覆盖组里最初固定的优先账号。复刻组和其他 Gemini 任务按排队时间统一排序领取（1.4.62 起），不会排在全部商品任务之后。单段重写最终失败后点「恢复任务」只重试这一段；点「恢复已有分段检查」则放弃这次重写。

新增状态：

| 状态 | 含义 |
| --- | --- |
| `remix_queued` | 等待拆解或复用原脚本换品 |
| `remix_analyzing` | 第一轮拆解 |
| `remix_adapting` | 原脚本已持久化，正在换品 |
| `remix_segmented` | 分段已创建，等待逐段检查 |
| `remix_rewrite_queued` / `remix_rewriting` | 单段重写等待/执行 |
| `remix_finishing` | 拼接、放行或放行后清理尚待完成 |
| `remix_done` | 已放入 TK 目录并完成版本清理 |
| `remix_deleting` | 已冻结整组，等待临时文件清理和删除 |

新增列均在 `lib/storage.ts` 做幂等迁移：

| 用途 | 列 |
| --- | --- |
| 参考视频 | `remix_video_key`, `remix_video_name`, `remix_video_type`, `remix_video_size`, `remix_video_seconds` |
| 计划和原脚本 | `remix_plan_json`, `remix_script`, `remix_analysis_blocks` |
| 各轮原始回复 | `remix_analysis_raw`, `remix_adaptation_raw`, `remix_raw_replies` |
| 商品/语言补充 | `remix_product_name`, `remix_spoken_language` |
| 片段原文和区间 | `remix_segment_script`, `remix_segment_start`, `remix_segment_end` |
| 单段重写 | `remix_rewrite_index`, `remix_rewrite_note` |
| 选用和检查 | `remix_selected_json`, `segment_checked_at` |
| 放行恢复 | `remix_release_task_id` |

整轮结果与子任务插入在一个 D1 batch 内写入，严格匹配父组状态、worker 和 batch_round。子任务 ID 由组、轮次、段序号决定，重复或旧执行器写回不能多建视频。每段独立进入既有 Seedance 队列，保持 submission journal、提交意图、原 Task ID 恢复不变。

- 失败后恢复：原脚本存在时只做第二轮，不重新上传视频；没有脚本才重跑两轮。
- 「重新拆解」清空原脚本，新轮次上传视频重来，原段版本保留；新区间不同的旧版本禁止选用。
- 「用原脚本重新换品」只跑第二轮，新建整轮版本。
- 「重新生成视频」复制该段同一条提示词、区间和快照，不经过 Gemini，原视频保留。
- 「重新写这段提示词」在同一个固定 Gem 的新空白对话上传商品图，用完整原脚本和选填修改说明请求指定一段；严格只接受一个相同区间的代码块，创建新版本。
- 默认选最新已下载版本；手动选用后按选用版本保存检查时间。检查时间不占用 `review_status`。
- 父组不会因为片段删光而自动删除，须手动删除整组。删除会取消本地执行器任务，清理本组拥有的临时视频、partial 和参考视频；商品库图片、无关文件和已放行成片保留。

备份恢复保留全部新列。历史未完成组/片段按既有规则标记失败，禁止自动发起远程生成；已提交 Seedance 的片段保留 Task ID 和历史恢复依据。已完成组保留完成状态。已有原分段时可点「恢复已有分段检查」，不会重跑 Gemini；段行里的「恢复原 Seedance 任务」只调用匹配的本地任务及既有 journal-aware 恢复入口，原记录缺失时停止，不新建替代任务。

## 拼接与放行

服务端重新核对每段正好一个选用版本、所有段齐全、全部已下载且 `segment_checked_at` 非空、区间与当前原脚本一致，再原子预留。按 `batch_index` 拼接，不能按版本轮次排序。

拼接仍用现有 concat-reserve/finish/cancel 和本机 FFmpeg。成功后调用 `VideoReview.approve`；单段组由同一组操作预留后直接调用该函数。视频移动、跨盘处理、命名、approval.json 收据和通过统计的逻辑保持不变。普通片段放行入口在界面、桌面和服务端都拦截；只有已通过整组检查并预留的单段组可以直接放行。

商品 ID 选填创建不影响生成，放入 TK 目录仍按原审核规则要求完整 ID；未填写时可在组内补全。放行成功后清理参与拼接的片段及所有未选版本，最后标记组完成。放行结果或清理 ACK 丢失，重启或「继续放行 / 清理」沿用收据恢复，不再次投放。

旧 `reference_remix_tasks` / `reference_remix_assets` 和执行代码保留用于备份兼容；新建入口只写新组。旧版列表只读并允许删除。

## 验证和真实页面确认

自动测试使用内存 SQLite、临时文件、Chromium 假页面和现有 FFmpeg 真实拼接用例；不读取真实 AppData，不登录或创建账号，不向真实 Gemini 发送任务。`remix-segments*.test.js`、`remix-page-flow.test.js`、`remix-ui.test.js` 覆盖计划、消息、校验、纠正、持久化、账号 hold、版本、整组放行、失去 ACK 后恢复和清理。

真实 Gemini 上仍需人工确认：视频上传处理完成时的页面形态、当前网页 Gem 对视频的支持、该指令的代码块首行遵循程度，以及同对话第二轮是否持续保持历史。平台拒答、网络地区限制和额度由实际账号环境决定，本轮没有用真实账号试跑。
