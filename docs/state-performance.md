# 状态写入与同步

`node scripts/bench-state.cjs` 在临时目录生成 500 条任务，每条 80 条合成日志，仅测单次 `log()` 的主进程调用耗时；落盘等待不计入改后的普通日志调用。Windows 本机样本：

| 指标 | 改前 | 改后 |
| --- | ---: | ---: |
| Seedance 状态大小 | 8,600,625 字节 | 6,411,913 字节 |
| Seedance 单条日志调用 | 32.0748ms | 0.1084ms |
| 主配置单条日志调用 | 2.2098ms | 0.1021ms |

普通 Seedance 日志/活动最多等待一秒。关键字段与最近一次成功持久化的任务比较，只要状态、Task ID、下载、提交记录或其他非日志字段变化，就立即保存并取消等待；提交日志和 prune/unmatched 的顺序保持原样。失败的关键写入在后续日志时仍立即重试，以保留原有恢复保证。退出前强制保存普通变化。

主配置不再保存 logs，旧日志迁移至 `logs/workbench.log`，内存保留 300 条。日志异步批量追加，按日或 5MB 轮转，只清理本程序命名的七天前轮转文件。损坏配置仍阻止启动，密钥和待写回队列仍使用原镜像持久化。

UI 快照仅含任务状态、活动等摘要和最近五条日志；三个流程的任务详情可以按需读取 Seedance 完整执行日志。批量变化每 250ms 合并发送。

本轮跳过旧任务归档：submission journal 的 durable 判断依赖任务列表中的 submitIntents/taskIds，删除旧任务可能造成关联丢失，也可能影响重新生成和历史查看。仅减少写入和传输，不改变任务保留规则。
