# 双段 30 秒（1.4.35）

创作中心的时长选择「双段 30 秒（15秒＋15秒，自动拼接）」。搭配输出「视频1｜上半段｜15秒」和「视频2｜下半段｜15秒」的 Gem；每段需要完整、独立的提示词。用户发送给 Gem 的文字保持原样，不添加隐藏指令。

一个网站任务对应两个持久化 Seedance 子任务，各提交 15 秒，共消耗两次视频生成额度。两个子任务沿用 Fast 优先及账号额度切换机制。失败后继续任务只恢复失败段，成功段保留。无法确认远端是否接受的提交仍保留人工核对，不冒险重复生成。

分段下载至该任务 review-videos 目录下的 segments/1 和 segments/2，均不进入发布目录。两段完整下载后，FFmpeg 统一为 1080×1920、30fps、立体声 48kHz，以自然硬切按顺序拼接，保留原声音；无音轨的一段补静音。生成结果在 12–18 秒内时，以画面和声音中较长的时长为基准，同步调整到 15 秒；声音使用保留音高的变速，保留完整尾音。仅补齐不足 0.8 秒的音画尾部差异；超出该差异或时长范围时明确报出实际时长并保留原片待检查。输出 30 秒 MP4，校验成功再原子提交。人物及音色一致性仍取决于生成模型。

审核只面向合成成片。通过审核、删除待检查任务及视频、重新制作时清理分段素材，保留防重复交付记录。拼接失败会保留原素材并重试。旧执行器无法领取双段任务。

提示词支持等价时长写法 `15秒`、`15.0秒`、`15.00秒`，也支持代码块正文丢失外层标题的情况；不会把口播词数预算当作分段标题。

分段标题与段内镜头标签分别识别：`视频1-镜头1`、`视频2｜分镜2`、`Video 1: Shot 1` 等属于正文，保持原样。支持 Markdown 标题、中文/全角编号和代码块语言标签；末帧、首帧、口播预算等说明不作为新的视频。确实缺段、重复编号、顺序错误或正文过短时，明确报告原因，不猜测截取、不重复发送给 Gemini。

已确认生成成功但实际不足 12 秒的片段，会只对该段自动补做一次，沿用原提示词与商品图片。另一段及原短片、原远端任务 ID 均保留；补做文件使用独立的 `segments/<段号>/retry-1/` 目录。补做关系与次数同时写入任务库和提交日志，重启后不会重复补做。若补做结果仍不足时长，停止自动生成并提示检查。超长片段、文件损坏和未确认提交结果不触发这项自动补做。通过审核、删除任务或重新制作时，同时清理原分段和 retry-1 补做片段，仅清理已知目录内的视频文件，不跟随目录链接。

## 失败处理方案

以下区分程序自动恢复与需要修正输入/账号的情况；不能把所有错误都通过重新生成解决。

| 情况 | 程序处理与恢复方式 |
| --- | --- |
| 完整双段被格式误判 | 1.4.35 修正镜头/分段识别；使用原提示词重新入队，无需重跑 Gemini。 |
| 真正缺段、重复段、段落顺序或时长说明错误 | 提示具体原因并在提交前停止。检查任务详情中的原输出，补全或调整对应段后继续，不自动编写用户提示词。 |
| Gemini 网络中断/页面超时 | 现有有限退避重试继续处理其他任务；次数耗尽后检查代理和连接再恢复。账号限流使用更长等待。 |
| Gemini 明确拒绝输出 | 保留回复和原输入，交由用户处理，不擅自替换 Gem 或附加文字。 |
| Seedance 登录失效、额度或并发限制 | 使用现有账号切换、等待额度/登录及限流退避；不替换成禁用模型。所有账号都不可用时需恢复登录或额度。 |
| 提交超时，无法确认平台是否接收 | 保存提交意图并阻止重复提交；到生成历史核对，已有结果取回，确认未生成后再新建。普通“继续”不会造成二次扣费。 |
| 平台明确拒绝参数（HTTP 400） | 保留具体响应并停止本次提交；核对图片、时长和模型支持后再恢复，不能靠无限重试解决。 |
| 平台生成失败或内容审核 | 已知可重试失败遵循设置中的重试上限；人脸输入错误 10043004 停止。内容问题由用户处理，程序不修改原提示词来绕过审核。 |
| 已生成但下载失败/链接未就绪 | 刷新同一个远端任务结果，按现有 1 分钟间隔重试下载；不重新生成。下载成功记录持久化，重启不重复交付。 |
| 某段不足 12 秒 | 只自动补做该段一次，成功段不动；再次过短停止补做并保留两次结果。 |
| 12–18 秒内轻微时长偏差 | 同步调整音画到每段 15 秒，保留尾音，合成后校验 30 秒。 |
| 超长、音画差过大、视频损坏或拼接失败 | 保留两段原片及远端 ID；本地拼接重试不消耗生成额度。根据具体问题恢复文件/工具，或由用户决定重做异常段，不强行拉伸掩盖坏片。 |
| 磁盘空间/权限/任务库写入失败 | 保留任务库和提交日志，无法可靠保存时暂停新提交；恢复存储后再继续，避免丢失远端任务 ID 导致重复生成。 |

历史任务库内已删除主任务的记录只作为审计依据，不自动重新创建或消耗额度。

构建前运行 `node scripts/prepare-media-tools.cjs`（build:win 自动执行），从 PATH 或 FLOWCUT_FFMPEG_DIR 复制 FFmpeg/FFprobe 至被 Git 忽略的 media-tools，再随安装包分发；最终用户无需另行安装。分发时保留使用的 FFmpeg 发行版许可证及对应来源。

验证：`node --test tests/dual-video.test.js` 覆盖分段解析、恢复、重试、聚合状态和真实 FFmpeg 拼接；`node tests/dual-video-smoke.cjs <win-unpacked>` 使用隔离数据验证打包后的 HTTP 路由和界面，模拟远端生成，不消耗账号额度。
