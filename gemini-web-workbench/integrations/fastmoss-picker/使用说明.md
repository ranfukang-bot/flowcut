# 0.10.1：修改条件立即重筛已有数据

完成或暂停扫描后，修改佣金、库存等条件会立即重新筛选已采集商品，不再继续显示旧条件的合格结果，也不重新发请求。明确显示当前结果实际采用的佣金、库存和数据页数。修改页数不会扩大已有数据，需要开始新扫描；新品榜最多可请求50页，实际可读范围仍受网站限制。

最低佣金为8时，未知佣金和“-”均不合格。输入无效时先清空合格展示并提示错误，避免旧结果冒充新条件的结果。扫描原条件和结果重筛条件分别保留。扩大原始采集范围仍需重新扫描。

新品榜快速模式不再每页固定等待5秒，改为页面完成加载后检查数据稳定。它仍读取列表页面，尚非新品榜列表全接口模式。

本地实际页面脚本回归包含：空佣金门槛改为8后排除“-”、改为11后排除10%、非法条件不显示合格结果、全程不新增读取请求。浏览器桥接连接失败，网页/接口佣金一致性与真实耗时仍待现场核验。

# 0.10：新品榜筛选

## 使用

1. 在 FastMoss 打开中文新品榜，选择国家、商品分类和上架日期区间，等待表格加载完成。
2. 在助手中重新读取已打开的榜单，选择标有“新品榜”的来源。
3. 设置佣金比例和库存区间，以及从第1页起读取的页数，然后开始筛选。

新品榜只检查佣金和库存。价格、销量环比和带货人数限制自动隐藏且不生效，不沿用销量榜的少于400人或“万字跳过”规则。带货人数读取到就显示；为空、0、-或含“万”，都不因此排除商品。合格新品统一显示在主结果表中。

佣金优先取详情中的当前值，读取不到时取榜单值；明确显示“-”不等于数值0。库存沿用网站“1000+”“43万+”等显示口径，不能确认上限的商品列入待核对，不冒充合格。CSV保留既有字段，新品主结果分组写为“合格新品”。

快速模式下，新品榜列表仍逐页打开读取，并校验上架日期与所选来源一致；每件商品通过已验证的详情接口读取库存、佣金和参考人数。此版未接入未经验证的新品榜列表接口。兼容模式使用页面读取全部数据。

日期不一致会暂停而不是筛选另一批商品。保持来源新品榜、助手及扫描页打开。销量榜旧功能和扫描记录保留；继续任务时不允许误选另一种榜单。

刷新助手页面确认“新版0.10”；如果仍是旧版，在扩展管理页重新加载本插件并重新打开助手。无需新增扩展权限。修改前的0.9.2文件夹已完整备份。

本地覆盖：实际dashboard.html/dashboard.js导入及交互、销量榜回归、新品榜条件隔离、未知人数、万人商品、未知佣金、库存下限、日期不一致与暂停处理。当前浏览器连接失败，未完成登录网站的现场验收；本地测试不等同于现场验收。

# 0.9.2：修复找不到当前榜单请求

不再依赖 performance 的历史网络请求记录。该记录有容量限制：真实页面出现商品表格已加载、250 条资源记录里却没有榜单请求的情况，0.9.1 因此错误中止。

当前参数按已核对的网站组件规则，从榜单地址读取并应用 page=1、pagesize=10、order=1,2 默认值；地址没有国家时读取页面已选国家。保留地址中的分类、日期、排序等参数，不读取或保存认证信息。

2026-09-09 在用户未刷新的真实印尼美妆榜上验证参数、两页榜单和20条详情，约11.15秒，18件唯一商品；少于400人的商品去重后1件。此为真实页面内调用，非扩展界面的现场验收。包含完整页面脚本导入、模拟扫描渲染及历史请求缺失用例的9项回归验证通过。

关闭并重新打开助手或刷新助手页面，确认0.9.2；如版本仍旧，再重新加载扩展。不需要刷新FastMoss榜单来补历史请求。

# 0.9：接口快速筛选

默认使用“快速模式”，复用当前登录的 FastMoss 榜单页面原有请求客户端。无需新增权限，不保存 Cookie、Token 或签名，不需要开启远程调试端口。

- 榜单按当前页面的国家、分类、日期、排序和每页 10 件读取，仍最多 25 页。
- 商品详情使用 `/api/goods/v3/base`，一次取得当前带货人数、价格、库存与佣金，不再逐件加载网页。
- 不使用榜单累计人数替代详情人数：实测同一商品榜单 335、详情 430，直接替换会误判“少于400”。价格也以详情为准，佣金沿用原版榜单优先规则。
- 库存仍保留“43万+”等显示口径，不将它当成精确库存；人数含“万”、零人数、“-”、未知值、环比、排序和导出规则不变。
- 顺序请求，最多每秒启动 2 个。2026-09-09 在已登录的印尼美妆日榜实测：1 页榜单 + 10 件详情共 5.36 秒（正常客户端，最多每秒启动 2 个请求）。此为页面内接口基准，扩展完整流程尚待重新加载后确认。完整扫描速度取决于商品数量、接口延迟和验证，不保证所有扫描几十秒完成。
- 接口验证、登录、权限拒绝会立即暂停，不自动重复请求。到“查看读取页面 / 处理验证”手动处理，然后继续。
- 普通网络错误重试两次，仍失败保留待核对记录。若网站客户端更新不兼容，可选“兼容模式”重新开始。
- 请保持助手和所选榜单开启。扫描期间不要改变所选榜单的地址或条件。继续时允许重新选择相同条件的榜单。
- 旧任务继续沿用原读取方式；要用快速模式，开始新扫描。上一次扫描保存在 previousScan，可用 JSON 备份导出。

更新方法：先暂停旧扫描并关闭助手，在 Chrome 扩展管理页重新加载本插件，再打开确认“新版 0.9”。原 0.8 文件夹已另行完整备份。

本地验证：`node --test api.test.mjs`。接口实测使用已登录页面的正常客户端，不自行伪造签名。

# 0.8：直接显示商品图片

在商品名称旁直接加载72×72缩略展示图，不等待滚动触发。图片地址取自扫描时榜单中的商品图片，不额外打开详情页找图片。图片失效或禁止外部加载时显示占位文字，不影响筛选。

每个结果分组每页显示30件，点击上一页/下一页切换。这是结果展示分页，和来源榜单页数不同；排序先对全部结果进行，再分页。CSV仍导出全部合格及待核对结果，不限当前30件。

进度更新但当前表格内容没变化时复用原表格，避免重复创建图片。图片展示尺寸不代表远程文件大小，实际下载量取决于网站提供的图片。

原插件文件夹已更新，关闭助手后到扩展管理页点击重新加载，再打开确认0.8。旧扫描未保存图片地址，显示暂无图片；重新开始扫描即可采集图片。无需新增权限。

# FastMoss 选品助手 0.7（基于0.5版）

以0.5版为基础，保留原有筛选、万字跳过、失败自动刷新两次及跳过、导出功能。本版不读取成交渠道和视频占比。

## 两项调整

1. 销量环比最低“-”、最高10000%：保留“-”和0%至10000%，排除负增长。两端“-”仍只筛选“-”。只有显式填写负数下限或不限制环比时才可包含负增长。
2. 排序菜单新增并默认选择“商品榜单顺序：从前到后（第1页起）”。先按来源页码升序，同页按原榜单先后排序，非零人数、零人数和“-”仍分别显示。结果增加来源页及页内位置；CSV沿用当前排序。

新扫描保存原榜单页内位置，即使中间有商品被过滤也不重新编号。已有0.5/0.6记录按保存的来源页码及收集先后排序；旧记录没有精确页内位置时只显示页码。排序以扫描时的榜单为准，不等同于网站实时更新后的排名。

## 更新

原插件文件夹已更新。暂停旧任务并关闭助手，在 chrome://extensions/（Edge为 edge://extensions/）点击本插件重新加载，再打开确认0.7。

已有结果无需重扫即可使用新排序，并立即隐藏“-”下限下的负增长。可继续旧进度；修改筛选条件后需开始新扫描。旧记录中的占比数据不再展示或补读。

## 使用

在FastMoss中文商品销量榜选择国家、分类、日期和排序。回助手重新读取并选择榜单，设置人数、价格、环比、佣金和库存区间，点击开始。每个榜单最多扫描前25页，结果可直接点击“查看商品”。

带货人数“少于400”严格不含400，含“万”直接跳过。价格按当地货币，范围与所填区间有重叠即保留。佣金填写百分数，库存填写件数。输入“-”表示明确显示的未知值，不等同于读取失败或0。库存“7万+”不能确认上限时列入待核对。

读取失败后刷新两次，仍失败则记录原因与链接并跳过；登录或验证码限制暂停。扫描需保持助手开启，可暂停续扫。CSV、JSON保存在可选导出菜单中。
